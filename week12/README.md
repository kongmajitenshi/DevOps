## CI / CD
- CI(지속적 통합): 코드를 합칠 때마다 자동으로 검사 → 테스트 → 빌드 → 이미지 게시까지 함
- CD(지속적 배포): CI 통과한 결과물을 실제 환경(쿠버네티스)에 자동 반영 → 다음 주
- 지금까지는 build, push, set image를 손으로 쳤는데 이걸 로봇한테 맡기는 것

## 워크플로 구조
- `.github/workflows/build.yml` 파일 하나가 워크플로 하나 (저장소 루트에 있어야 함)
- 읽는 순서: 언제(`on`) → 어디서(`runs-on`) → 무엇을(`steps`)
- `uses`: 남이 만든 액션을 가져다 씀 / `run`: 내가 직접 명령 실행
- 각 step은 종료 코드로만 판단함. 0이면 초록✓, 0이 아니면 빨간X라서 그 뒤 단계는 안 돌아감

## 검사 단계
- 문법 검사(compileall): 파이썬으로 읽히기만 하면 통과
- 린트(ruff): 실행 안 해도 오타, 정의 안 된 변수 같은 걸 잡아냄
- 테스트(unittest): 실제로 요청 보내서 결과가 맞는지 확인함. healthz가 500을 반환하는 것처럼 린트로는 못 잡는 오류를 잡음

## 태깅
- latest는 계속 덮어써져서 어제 버전이 뭐였는지 모름
- 커밋 해시(sha)로 태그 달면 어떤 커밋으로 만든 이미지인지 추적할 수 있고 롤백도 가능함

## 실습하면서 느낀 점
- 일부러 오타 내고 push하니까 Actions 탭에 빨간X가 뜨고, 고쳐서 push하니까 초록✓로 바뀜. 굿.
- 브랜치 보호 규칙까지 걸어두면 main 보호해줌. 혼자서 쓸 일은 잘 없을 것 같은데 확실히 협업할 땐 많이 쓸 듯.
